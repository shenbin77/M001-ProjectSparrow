# M001 — Project Sparrow / 赤雀 GDD

状态 ACTIVE；本周唯一主开发。版本0.1，2026-09-11。首周窗口9月11–17日。本文区分长期愿景与首周验收，所有新增实现选择须写 DECISIONS.md。

## 1. 产品定义与承诺
Mahjong Sports RPG / Mahjong Club Manager。玩家继承一家快倒闭的雀馆，招募牌手、培养明星、训练技能、经营俱乐部、踢馆，从城市/地区/全国/亚洲走向世界职业联赛，建立世界第一麻将王朝。不是普通麻将客户端，不是麻将打怪 Roguelike。

桌内：标准麻将是真正的核心比赛规则。V1 优先 Riichi（日麻/立直麻将），海外已有认知基础；未来可扩四川、港麻、国标与地区赛事。具体赤牌、食断、流局、比赛长度等规则参数须冻结并公开，不把未实现规则默认为完整支持。

桌外：角色IP、俱乐部、剧情、成长、联赛、经营、宿敌、转会、退役、师徒传承是差异化。核心循环：比赛 → 资源/声望 → 招募/球探 → 训练 → 学习/替换技能 → 成长 → 经营 → 更强对手 → 晋级/剧情/角色 → 再战。

北极星：玩家愿意再打一场，并关心自己培养的牌手与俱乐部。首周验收是可玩的闭环而非终局内容数量。

## 2. 世界观与职业结构
中国文化为根，开篇可用有中国沿海城市气质的架空城市，避免真实俱乐部和商标。整个舞台是架空全球职业麻将世界，不限定中国。麻将是类似足球+扑克+电竞的全球顶级智力运动之一。

职业世界包括全球职业协会、地区联盟、豪门、弱旅、青训、新秀、自由球员、MVP、季后赛、总决赛、世界赛。职业联盟本身就是世界观，不需要神魔宇宙。成长阶梯：破败雀馆 → 街区踢馆 → 城市联赛 → 职业资格赛 → 全国联赛 → 亚洲巡回 → 世界职业联盟 → 世界冠军。

首周只覆盖这条阶梯的早段与小型联赛；后续层级保留数据扩展点，不假装已制成。

## 3. 用户体验与比赛
玩家应能从俱乐部进入一场真实麻将比赛，做合法操作，看到公开状态与结算，再回到管理界面消费奖励，改变阵容/培养并进入下一挑战。规则库输出合法动作与结算，UI不得自创第二套规则。AI 只能访问自身手牌与公开信息，不得偷看隐藏牌墙。

完整单局需明确发牌/摸打/轮转、合法行动、终局、分数与奖励触发。Riichi 完整性必须经专项测试，包括吃碰杠、立直、和牌役与符番、振听、宝牌、流局等实际选择支持的范围。首个可运行场景可先是受限切片，但必须标“原型/未完整规则”，不能把摸打演示交成最终标准日麻 RC。

暂定：首周单机，玩家控制一个席位，AI 控制其余席位；俱乐部管理决定上场选手。该控制方案为低风险实现假设，需实际手感测试。比赛时长设置需与1–2小时职业循环协调，但不能以伪造规则来提速。

## 4. 角色/IP：固定角色与生成选手
正式版约15–30名核心固定IP人物，有固定名字、造型、性格、背景、关系、专属剧情、技能/牌风、成长弧。目标是每个人能被记住，采用成熟类型语言但不复制火焰纹章等角色或表达。

另有长期自动生成的职业选手，用于青训、选秀、自由市场、外援、新赛季 Newgen。生成姓名、出身、年龄、性格、属性、潜力、牌风、隐藏缺陷、小故事。生成内容须遵守世界观和数据约束，不能只随机数值无人物。

### 数据合同
每个角色至少预留：稳定ID、名字、年龄、出身、当前能力、潜力、读牌、进攻、防守、心理/大赛稳定性、体力/状态（可轻量化）、性格、招牌打法、先天天赋、4个可装备后天技能槽、关系网、合同、职业记录、俱乐部归属、成长曲线。固定角色另有欲望、缺陷、背景、成长弧、专属剧情引用；生成选手有生成种子/来源以支持复现。

首周 Day2 达4个核心角色，Day4 达8个。视觉均占位。角色个性至少体现在数据、文本、训练/关系或对局行为的可解释差异，不能靠稀有度标签冒充IP。

### 培养和技能
技能可学习、替换、洗练/重构 Build，不做固定SSR永远固定5技能。来源是训练、教练、师徒、剧情、比赛和赛事奖励。同一角色能走不同牌风。四个后天槽有明确索引、空槽、替换和非法技能处理；成长消耗和收益必须可见，资金不足不得扣成负数。

暂定首周技能作用于桌外训练、经验或AI决策倾向，不改变牌墙概率或非法动作。具体效果尚需数值测试，不将该暂定方案冒充所有长期技能最终设计。

### 退役与传承
不是合成，不吃卡。角色进入 Retirement / Hall of Fame / Legacy，能成为教练、球探、导师、解说、开新俱乐部、参与后续剧情。招牌技能与经验通过师徒传给新人，多赛季老将保留历史与身份，不能当垃圾材料吞掉。首周保留数据与文档，完整多赛季退役内容不强塞进RC。

### 招募与重复角色
首周无真钱抽卡，允许游戏内球探券/招募十连，验证角色招募吸引力。招募必须能说明费用、结果、阵容归属与重复处理；实际范围可先单抽再批量。未来重复角色可转故事碎片、皮肤、语音、特殊演出、训练资源、Scout Token，不简单加星战力。未来货币化尚未定案。

## 5. 阵营 / 俱乐部设计
每家俱乐部预留视觉语言、招牌牌风、人才哲学、历史、宿敌、核心角色、球迷文化。至少明确以下三类：

| 俱乐部 | 视觉语言 | 牌风与人才哲学 | 历史/宿敌/球迷方向 |
|---|---|---|---|
| 赤雀 / Crimson Sparrow | 红、米白、黑；磨损布料；草根街头；原创雀徽 | 攻击性、热血、发掘被忽略新人 | 继承前辈传奇，从破败中重建；具体宿敌角色待原创数据落地 |
| 黑龙馆 | 黑金、传统冠军的压迫感 | 控制、压迫、老牌豪门训练体系 | 历史强队与赤雀形成阶层/竞技冲突；具体史实均架空 |
| 白鹤院 | 白、银、冷蓝；精致克制 | 学院派、防守、冷静 | 以系统训练见长；与赤雀形成方法论对照 |

上述后三列扩展细节属于设计方向而非已完成剧情。未来数据科技派、富豪明星队、海外豪门可进入新篇章。Day2 两家俱乐部，Day4 3–4家对手俱乐部（不应把玩家本队误计为对手数量）。

## 6. 剧情与经营绑定
开篇：主角继承濒临倒闭的麻将馆/俱乐部，债务、几位年轻选手与前辈传奇一起留下；竞争者逼债/踢馆，玩家必须在有限时间内重建名声。此为用户建议的开场基线，具体金额、期限、人物名是待实现假设。

事件池：明星加薪、新秀与老将冲突、青梅/宿敌入豪门、传奇老将将退役、挖角、赞助商要求、媒体压力、大赛失利/复仇、关系/师徒/背叛/重逢。选择必须影响士气、关系、合同、阵容、资金或后续剧情，不能全部变成无后果长对话。

强对手是职业牌手而不是怪物：进攻王、防守大师、逆风王、天才新人、退役冠军复出、世界冠军Boss。新角色通过新地图 → 新剧情 → 新俱乐部 → 新角色 → 新玩法登场，不从商城凭空掉SSR。未来篇章包括亚洲、日本/东亚、北美、欧洲。

首周最少实际接通简单剧情事件与可见后果；长期关系网与赛季故事在数据上预留，不声称已完整开发。

## 7. 美术、声音与呈现
本阶段禁止生成正式立绘、角色海报、角色特效图。只用占位头像、色块、几何剪影或合法临时素材；人物数据和故事继续开发。

最终方向记录但本周不生产：原创热血漫画角色辨识度；高矮胖瘦、年龄、姿态、发型、服装强剪影差异；高级手绘/赛璐璐/局部厚涂、电影级光影材质。避免塑料皮肤、同脸、七彩霓虹堆砌。阵营通过纹章、服装、牌背、胸章、奖杯、俱乐部空间一致表达。赤雀徽章可研究原创红雀+中张牌意象，不复制现有品牌。未来动画结构70%共用麻将动作骨架+20%阵营风格+10%角色招牌。

## 8. 公平性、联网与商业边界
Classic Ranked 完全公平，角色只能提供外观、语音、和牌演出、表情、桌布，不能影响发牌、摸牌、和牌概率，不做P2W。未来 Ability League / Character Battle 可明确公开技能影响玩法，独立娱乐/Build模式，不污染排位。本周不实现联网、lobby、matchmaking，只调研候选，避免扩大Scope。

## 9. 首周验收与工程要求
- Day1：可运行麻将场景/原型、数据模型、测试基线和完整文档。
- Day2–4：完整单局、角色培养/4技能槽、存档、踢馆、奖励、招募、升级、剧情、AI自动局、小型联赛与资金/阵容。
- Day5：整合UI、教程、英语优先、本地化框架、实际1–2小时职业循环。
- Day6–7：规则/崩溃/卡死/存档/数值/教程/构建审查，Windows RC、运行验证、版本/已知问题、Steam材料。

存档须保留版本、资源、阵容、角色成长/技能、进度与事件；坏档、重复结算、读档状态不一致须测试。局内/局间存档边界在 Architecture 明确，不暗示任意时刻都能保存。依赖经许可审查，Godot优先，Adapter隔离规则与展示。

## 10. 未验证项与发布边界
目前 GDD 是设计基线，不是功能完成证据。规则覆盖、AI表现、1–2小时体验、数值、可运行 Windows RC、真人测试、Steam账号与审核状态都必须以实际记录验收。Steam 外部等待不改变9月17日本地代码/Build目标，但不能许诺7天必定公开售卖。发行授权/付费/条款/不可逆发布需用户确认。
