# M001 Architecture / 实现合同

状态：Day 1，2026-09-11。目标平台 Windows x64。此文档描述目标与适配边界，不表示全部已实现；实际状态以 CURRENT_STATUS.md 与测试报告为准。

## 技术选型
Godot 4.6.1 standard / GDScript，Compatibility renderer；使用原生 Control 组件，不生成角色立绘。规则层直接引入 MIT kobalab/majiang-core 1.4.1 的原始 lib，通过独立 Node 进程交换 JSON。这样重用已有规则、计分、向听数、合法动作与对局状态机，不把一个星期浪费在移植规则上。Node 进程不监听网络端口。首日允许便携开发包，Day7必须验证干净机器上的正式导出。

## 模块与权威边界
1. `backend/`：RuleAdapter，为唯一牌局权威；UI不决定是否可和、分数或牌山。规则固定，角色训练不得修改洗牌分布。
2. `vendor/majiang-core/`：冻结第三方代码，保留许可证与来源提交；不直接修改，升级必须重跑上游测试与适配测试。
3. `game/`：Godot UI、Career状态、俱乐部管理、存档。UI只显示自己的手牌、公开弃牌与公开副露，AI不得读取其他玩家手牌。
4. `data/`：角色、俱乐部、技能和事件；稳定字符串ID，禁止用名字作外键。角色正式目标字段见GDD。
5. `tests/`：规则适配测试、非法动作、确定性重演、批量AI对局、成长事务、存档恢复。
6. `docs/`：产品与开发合同；`CURRENT_STATUS.md` 是本项目当前进度真相源。

## RuleAdapter协议
JSON请求：new、action、auto；每个响应携带版本化状态与面向UI的快照。state包含可重演种子与合法决策历史，外部输入必须验证。具体字段以backend README为准。后端失败不得用随机胜负或假计分掩盖，UI应保留旧状态并显示错误。

状态转换：Club → Match → PendingChoice → Resolve → MatchResult → RewardOnce → Club。比赛奖励只根据权威结果发放，不能通过重绘/重复按钮再次领取。初日局制可是一局挑战，后续东风战/联赛不改变Riichi规则。训练、招募、装备技能不允许在比赛中改写快照。

## 存档一致性
schema_version、资金、声望、队员ID、等级经验、技能槽、已结算比赛ID、当前赛事、叙事旗标。先验证结构与数值，再应用；先写临时文件再替换；覆盖前保留.bak。损坏存档不得自动覆盖。未知未来schema拒绝读取并提示。Day1允许仅局外保存；局内恢复未实现必须在界面说明。

## Worker / 审查合同
L1数据、文案、单测、普通UI优先本地Qwen；L2独立模块优先OpenCode可用免费/低价模型；L3复杂集成与存档一致性由Codex；L4架构与Release由Codex。OpenCode是执行器，不是模型；配置存在不等于服务可用。任何任务需有：输入文件、允许修改路径、验收命令、禁止事项。Worker产物先隔离、测试、Critic审查，再进主线。失败次数、原因与成本标unknown而不是虚构。

## 验证与发布门
上游单测通过不等于我们的完整游戏通过。必须依次验证：规则库→适配层→Godot解析/无头运行→UI交互→Windows启动→成长/招募/训练/技能/剧情→存档失败路径→1–2小时真人职业循环。至少正常、边界、失败路径。计划1000局AI跑测，记录种子、结果、超时/异常，不用AI假装真人喜欢。

Day7 Release Gate：干净Windows可运行，无P0崩溃/卡死/损档，标准日麻合法动作/计分可回归，8名角色和3–4家对手俱乐部，英语教程，本地化键，1–2小时职业循环实际试玩，有版本/许可证/哈希/已知问题/回滚/Steam材料。未过项必须保留，不降低为“基本完成”。

## 不做
本周不开发联网匹配、反作弊服务器、真钱抽卡、完整世界赛、正式角色动画、自动市场雷达、可视化Agent工厂。未来Classic Ranked服务器权威且纯公平；Ability League独立规则池。单机可修改的存档不能复用为公平竞技权威。

## 生产就绪审查
发布时六维评分：安全25、弹性20、可观测20、部署15、数据库10、容器10。单机无数据库/容器项写不适用并解释，不能为了满分虚构服务。分数不能替代功能验收。遥测首版本地匿名事件，不默认上传个人信息。
