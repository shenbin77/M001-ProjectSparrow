# M001 — 7-Day Sprint Plan

基线：2026-09-11；时区 Asia/Shanghai。Day7 = 2026-09-17。目标 Windows 可玩 Release Candidate，Steam 推进至平台允许且已授权的最远状态；不承诺7天公开售卖。G002 仅完整文档归档，不开发。

## 执行规则与阶段
当前阶段为已明确需求后的文档基线/原型实现，不能重启漫长需求会议。先检查目录、Godot、OpenCode、Qwen与现有可复用资产；正式文档落盘；GitHub候选评估；马上启动最小工程。第一天必须可运行，不允许整天只产架构。

Builder 实现和自测，Critic 六维审查且不改代码，Evaluator按原始目标裁决。Worker先测试再合并，主分支可构建。L1本地Qwen、L2廉价Coder/OpenCode、L3/L4 Codex；环境不可用记录事实和降级，不假称并行成功。每任务有 acceptance criteria，每次变更有验证与回滚。任何架构/Agent优化连续2小时无可运行成果立即停。

每6小时写 CURRENT_STATUS：完成、进行中、阻塞、下6小时、Codex消耗、Worker成功率（成功/总数；未知或N/A不冒充0）。自动推进以真实调度可用为前提。付费、Steam账号授权、不可逆发布、法律条款同意需要用户确认。

## Day1 — 9月11日：基线与首个可运行切片
交付：项目初始化；8份正式文档；GitHub复用/许可筛选；最小麻将可打闭环；角色/俱乐部/技能/存档数据模型；自动测试基线；至少一个实际可启动Build/场景。

顺序：环境基线 → 文档落盘 → 候选与许可证 → Godot优先工程 → 最小合法动作与终局路径 → 启动测试。其他框架只有本机明显成熟且更快才采用，写 DECISIONS。源码存在不等于Build存在。

验收：记录实际引擎/依赖版本；场景启动无致命错误；玩家能进行动作并抵达原型终局；测试可重复运行；规则尚缺部分明确标注，不称完整日麻。复用报告逐项含repo、活跃/维护、测试证据、适配、依赖、许可和预计节省时间。

## Day2 — 9月12日：单局与培养存档
交付：单局麻将完整运行；4核心角色占位；2家俱乐部；训练、经验、4技能槽基础；存档。

验收：开局至终局自动/手动路径；已声明Riichi规则覆盖核验；训练扣费加成长正确；技能装卸/替换与非法输入测试；保存读取恢复角色、资源与进度；坏档和写入失败不损坏唯一有效存档。规则未完成时标红阻塞，不用管理UI掩盖。

## Day3 — 9月13日：职业闭环
交付：踢馆节点、胜负奖励、球探/招募、升级、简单剧情事件、AI自动跑局。

验收：比赛→结算→奖励→招募/训练→下一节点全链路；输局也能继续或明确结束；结算不可重复领奖；资金不足/招募重复/技能空槽可处理；至少一个剧情选择改变可观察状态；AI无死循环且不访问隐藏牌。

## Day4 — 9月14日：小型联赛与自动平衡
交付：小型联赛/段位、资金/阵容管理、3–4家对手俱乐部、8个角色、批量AI Playtest与初步平衡。

验收：排名、晋级、赛程、阵容合法性；人数口径不把玩家队计入对手；角色数据校验无ID冲突；批量局记录种子、终局、异常、时长、奖励及胜负分布。样本量暂定先100局冒烟、稳定后扩1000局，实际完成数原样记录，不能以少量样本宣称平衡完成。

## Day5 — 9月15日：可理解的职业体验
交付：统一UI/UX、教程、英语优先、本地化框架、完整1–2小时职业循环。继续占位角色图。

验收：从新档到比赛/成长/晋级无需开发者指导的教程路径；文本走本地化键；常用分辨率可操作；真实计时试玩或日志验证1–2小时内容而非估算；保存退出重开可继续。AI测试不能代替真人可理解性测试；缺真人记录为未验证。

## Day6 — 9月16日：攻防审查与发行材料
交付：Critic攻击崩溃、存档、规则、卡死、数值、教程和Build；修复后回归；Codex Architecture/Quality Gate；Steam商店文案、截图/Trailer脚本、素材清单。

验收：阻断缺陷清零或明确导致No-Go；规则/计分对成熟库和固定案例；坏档/中断写入/重复结算/长局；资源来源和许可证检查；截图来自真实版本，不伪造正式美术或未实现内容。修复由Builder实施，Critic复核，Evaluator独立对照目标。

## Day7 — 9月17日：RC与Windows分发
交付：版本化 Windows RC、安装/解压/启动验证、回归结果、已知问题、运行说明、校验值、可回退版本；Steam可执行的最远发行状态；若等待/授权阻塞则提供可直接分发Windows试玩包与完整准备材料。

验收：干净环境/独立导出目录运行；核心循环实际跑通；存档重启恢复；包内依赖与许可齐全；版本对应源码和测试记录。不能把网页原型称Windows原生RC，不能把编辑器可运行当独立导出成功。Steam提交与公开发布需真实平台回执和授权。

## 每6小时控制点模板
- 当前版本/阶段/工作树状态。
- 已完成（证据链接）；进行中（验收标准）；阻塞（错误与最近核验点）。
- 下6小时最多3项关键路径任务；负责人和预计验证方法。
- Codex额度：可读值与时间，未知则未知；Worker：成功/完成任务数与失败原因。
- 距离下个可运行成果的时间；若超过2小时，停止非关键工厂工作。
- 新风险、范围变化、回滚点、下一次检查时间。

## Release Gate 与不可偷换的标准
Go 必须同时具备实际Windows包、真实可玩职业循环、公开规则边界、存档回归、无阻断缺陷、依赖许可、已知问题、运行证据。完整标准日麻若仍缺核心规则，应降级为明确的原型/预览，不宣称满足原定RC。时间到了不自动变通过。

生产就绪审查按安全25%、弹性20%、可观测性20%、部署15%、数据10%、容器10%，本地单机不适用项写N/A。所有测试区分已执行通过、已执行失败、未执行。

## Steam 外部时间线
记录 Developer/App授权状态、Direct付款日期、Coming Soon起始、审核提交/返回日期、官方等待规则与来源。没有实际账户数据，最早发布日写未知。核实后的最早日期取各等待条件的最晚满足时间，并计入审核不确定性。付款/条款/授权/不可逆发布暂停请用户确认；无权限先完成材料，不能假称已提交。

## 风险应对与范围取舍
优先削减内容数量/演出与未来系统，保留核心真实麻将、成长、存档和可运行包。不得为赶进度伪造规则、结果或试玩时长。Godot/规则适配失败从最新已验证点恢复，用成熟可验证路径，不无限造桥。G002、正式角色图、多人、真钱抽卡和超级Factory保持冻结。7天后的增长、变现、规模化需用户/市场真实验证，不包含在首周完成声明。
