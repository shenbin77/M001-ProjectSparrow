# AI Game Factory — Master Vision

版本：0.1 / 2026-09-11。本文件是公司方向、产品优先级与执行边界的正式基线。用户决策为确定要求；标注“暂定”的内容是可回退实现假设，不是已验证事实。

## 1. Goal / Non-goals / Done-when / Return
- Goal：7天内完成 M001 Project Sparrow / 赤雀的可玩 Windows Release Candidate，并把 Steam 发行推进到平台允许且用户已授权的最远状态。
- 时间窗口：Day 1 为 2026-09-11，Day 7 为 2026-09-17（Asia/Shanghai）。这是交付目标，不是已有成品或必定公开售卖的承诺。
- Non-goals：本周不开发 G002，不先搭超级工厂，不做正式角色立绘，不做真钱抽卡，不做联网竞技，不把完整世界联赛终局塞入首周。
- Done-when：用户能运行 Windows 包，实际体验麻将比赛与俱乐部成长闭环；规则、存档、流程、构建通过明确测试；已知限制公开；Steam 状态以平台证据为准。
- Return：工程、版本化 Windows 分发包、正式文档、复用与许可证记录、测试/缺陷/发布记录、Steam 材料及外部阻塞。

## 2. 公司北极星
长期建立 AI 原生游戏公司，而不只是完成一款游戏：市场机会扫描 → 概念生成 → Builder → Critic → Prototype → AI Playtest → Evaluator → Human Test → KILL/SCALE → Production → Steam/其他平台发行 → Telemetry 回流。

产品拖着工厂长出来（Product drives Factory）。任何 Factory 功能都必须回答“它如何直接缩短当前 M001 的7天交付路径”；不能回答就延期。当前不做通用代理平台、复杂任务市场、全自动发行系统、大规模遥测平台。连续2小时架构/Agent/工厂优化未产生可运行成果，立即停止，回到可运行游戏。

产品北极星是：玩家愿意再打一场，并因为自己培养的牌手和俱乐部而留下。不是生成多少代码、多少角色或多少代理。长期衡量留存、完成职业循环比例、角色记忆与情感连接、重复游玩、购买意愿；具体阈值等待真实数据，不捏造验证成功。

## 3. 产品组合
### M001 — ACTIVE
Mahjong Sports RPG / Mahjong Club Manager。从快倒闭的赤雀俱乐部出发，打标准麻将，招募与培养牌手、管理球队、踢馆、参加联赛，建立世界第一麻将王朝。不是普通麻将客户端，不是麻将打怪 Roguelike。桌内是标准竞技规则；桌外是角色IP、职业生涯、经营、剧情与传承。

### G002 — PARKED / READY
Character-Driven Tactical RPG，中西方黑暗幻想，以角色与 Legacy / 传承为核心。完整设计保存在 G002_PROJECT_LEGACY_GDD.md。本周不能分配实现、正式美术、原型或依赖集成工作。只有用户重新排优先级，或后续有证据支持转换，才启动。

## 4. 团队与模型路由
- Codex = Lead/CTO：总架构、拆任务、复杂集成、难Bug、Code Review、开源许可审查、最终验收与 Release Gate；额度有限，不包办低价值批量劳动。
- OpenCode = 主要 Agent / 任务调度层。
- 本地 Qwen / Qwen-Coder 与可用免费/低价 coder = Worker：普通编码、JSON、单测、UI、批量修改、简单Bug、剧情数据。
- L1（文本/JSON/简单UI/单测/批量数据）→ 本地 Qwen；L2（独立Feature/普通重构/中等Bug）→ OpenCode 廉价/免费 coder；L3（跨系统架构/复杂Bug/存档一致性/联网/性能）→ Codex；L4（Release Review/Architecture Gate）→ Codex。
- Worker 连续失败或任务跨系统复杂时升级 Codex；失败次数和原因必须记录，不能为维持路由而无限重试。暂定最多2次同类失败即升级，待实测调整。
- 必须实际检查环境和可用模型；不存在的 Worker 不得宣称正在运行。不可用时记录降级执行成本，优先恢复关键路径。

Builder 实现与测试，不自行宣布验收；Critic 只审查不改代码，从需求完整性、逻辑、边界、质量、覆盖、实际运行六维攻击；Evaluator 对最初目标逐项裁定。Worker 修改先测试、Critic 通过再合并，主分支保持可构建。最终验收不能把“文件存在”当作“可玩”。

## 5. 执行纪律
每项任务必须附：目标、非目标、输入/输出、负责人、验收标准、验证方式、失败路径、回滚点。最小必要改动，不无关重构。缺少低风险细节用显式暂定方案推进；关键外部权限不能假装具备。

每6小时更新 CURRENT_STATUS.md：已完成、进行中、阻塞、下6小时任务、Codex额度消耗、Worker成功率。额度若工具不能读取写“未知”，Worker 成功率必须写分子/分母及口径，无任务则 N/A。自动推进需要真实调度，不把对话结束后的持续运行当既成事实。

真钱支付、Steam账号授权、不可逆发布、法律条款同意须用户确认。不得提交密钥；不得破坏系统配置或个人数据。用户要求快并不等于可以伪造平台审核或绕过许可。

## 6. GitHub-first
先调研再复用，不无意义重写。候选涵盖规则引擎、和牌/听牌/向听/计分、麻将AI、Godot麻将/卡牌/UI、对话、存档/状态机、联赛/排名/数据、Steamworks、未来多人网络/lobby/matchmaking、测试框架。

每项记录 repo、活跃度、测试覆盖证据、语言/引擎适配、依赖、维护状态、LICENSE、预计节省时间和集成风险。分类：可直接复用 / 需要适配 / 不建议 / 自研。优先直接库，其次 Adapter，最后自研；成熟库存在却自研，必须写 DECISIONS.md。

优先 MIT/Apache/BSD/MPL 或明确允许商业使用的许可；MPL 等仍需检查具体义务。GPL/AGPL/LGPL/不明许可不得直接合入商业主仓，除非有明确隔离策略和法律影响评估。保留版权和许可证；仓库代码许可不代表其美术/字体/音乐同许可。禁止复制火焰纹章、雀魂等受保护表达。

## 7. 美术与商业边界
本阶段不生成正式角色立绘、海报、角色特效。仅占位头像、色块、几何剪影或可验证合法临时资产。人物数据和剧情不能因此停工。未来正式风格是原创热血漫画辨识度，不能廉价同脸二次元堆砌。

第一阶段只有游戏内球探券/招募十连，未承诺最终付费模型。未来如 F2P/手游化，重复角色可转故事、皮肤、语音、演出、训练资源或 Scout Token，不简单重复升星碾压。Classic Ranked 永远公平：角色不能改变发牌、摸牌、和牌概率；能力玩法只能在明确标注的独立娱乐模式中。

## 8. 交付与证据
2026-09-17 的首要内部目标是 Windows RC；不是完整世界冠军内容。Steam 新开发者/新App可能有 Direct 等待、Coming Soon 最短展示与审核周期，必须实时核实并记录账户/App实际日期，未知则写未知。外部等待不能挤掉本地包和测试；无授权时只能准备材料，不假称已提交。

必须维护：00_MASTER_VISION、M001/G002 GDD、7_DAY_SPRINT_PLAN、ARCHITECTURE、DECISIONS、OPEN_SOURCE_REUSE_REPORT、CURRENT_STATUS。发布时另附运行说明、版本、已知问题、测试结果与回滚记录。生产级交付需安全基础25%、弹性20%、可观测性20%、部署15%、数据10%、容器10%的审查；不适用项显式 N/A，不虚构高分。

## 9. 决策与学习
原型→AI测试→Evaluator→真人测试形成证据后再 KILL/SCALE；不得凭兴奋或代码量宣布成功。先完成当前产品，再提取真实复用能力进入 Factory。所有新增假设在 DECISIONS 中记录来源、影响、验证方式。长期增长/商业化/规模化不因7天冲刺被宣称完成。
